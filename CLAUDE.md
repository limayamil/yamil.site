# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
npm run dev       # astro dev — local server at http://localhost:4321
npm run build     # astro build — outputs to dist/
npm run preview   # serve the production build locally
npm run check     # astro check — type-checks .astro files and the project
npm run test      # Vitest unit tests for the UI sound layer
```

There is no linter configured. The focused Vitest suite covers the optional UI sound layer.

## Architecture

This is a single-page Astro portfolio site (no client-side framework — Tailwind v4 for styling and two vanilla-TS entry points for runtime behaviour).

**Data-driven content.** The page is assembled from three data sources, not hardcoded markup:
- [src/data/profile.ts](src/data/profile.ts) — name, role, bio, capabilities, contact links, location/timezone. Typed against exported interfaces (`Profile`, `Capability`, `Localized`) rather than inferred from `as const`. Consumed by [Intro.astro](src/components/Intro.astro), [Axes.astro](src/components/Axes.astro) and [Links.astro](src/components/Links.astro).
- [src/data/track.ts](src/data/track.ts) — the employment record: fourteen entries, each with a `role`, `company`, `start`/`end` as `YYYY-MM`, an `axis` and a one-line `note`. Consumed only by [Track.astro](src/components/Track.astro). Two fields deliberately break the `{ es, en }` rule: `role` and `company` are plain strings, because a job title goes by its English name in both languages — the same call `Capability.title` already makes. Dates are formatted per language at build time rather than stored twice.
- [src/data/projects.json](src/data/projects.json) — project entries, loaded as an Astro content collection via `file()` loader and validated against the Zod schema in [src/content.config.ts](src/content.config.ts). Consumed by [ProjectList.astro](src/components/ProjectList.astro) (filters `featured`, sorts by `order`), rendered as a grid tile by [ProjectCard.astro](src/components/ProjectCard.astro) and as a case page by [ProjectDetail.astro](src/components/ProjectDetail.astro). Every visible string is a `{ es, en }` pair, same as `profile.ts`; JSON takes no comments, so the field-by-field reasoning lives in the schema.

Three fields in a project are enums, and a typo in any of them **fails the build** — the same posture as an unknown `toolIcons` key:
- `axis` — `engineering | motion | ops`. This is the same key as a capability's `icon` in `profile.ts` **and as a track entry's `axis` in `track.ts`**: the capability chips in the left column *are* the bento's filter — hovering one dims the work on the right that is not it, clicking one commits that as the filter (and clicking it again clears it). A track entry carries its `axis` too — it drives the glyph in that entry's node and its sr-only label — but nothing on the record currently filters or highlights by it. Renaming one without the others still silently breaks the bento's filter.
- `tier` — `primary | secondary | tertiary`. Size in the bento, and the only signal of importance the design has.
- `shape` — `horizontal | vertical`, read only when `tier` is `secondary`.

`profile.ts` and `projects.json` hold real content. Updating either is expected to be safe without touching layout code — subject to the copy and grid budgets below.

**The right column is a bento grid with two views and one URL.** `.projects` holds both the index (the grid, plus a `.filter-bar` that stays `hidden` until an axis is on) and all three current cases at once; `data-view` picks one, the same trick `html[data-lang]` plays with the two languages. `#caso/<slug>` is the entire router — tiles are real anchors, so a click changes the hash on its own and `hashchange` is the single entry point, which is what makes the back button, a shared link and a ctrl-click all arrive through the same door. Closed cases carry `hidden` (the attribute, not a class) so they stay out of the accessibility tree and so `#caso/slug` degrades to "nothing happens" with JS off.

Two things about it are measured, not chosen, and **both are in [design.md §8](design.md)**:
- **The tile's copy scrim hangs off the copy, not off the tile** (`.tile-body::before`). A tile is a fixed cell but the copy in it is not, so a gradient expressed as a share of the tile is a guess that a two-line title breaks — the first version left a tertiary tile's axis line at 1.9:1 over a white frame. Pinned to `.tile-body`, the opaque run covers the copy plus its padding and the ramp starts exactly where the text stops, at any tile height. Its α (0.93) is what puts `--color-primary-ink` back over 4.5:1 against the brightest artwork possible; moving it means re-running §8's measurement.
- **No tile is ever one row tall, and desktop always shows at least three cases per complete row.** A single-row tile puts ~105px of copy over a sliver of artwork, so `.tile` carries a `grid-row: span 2` floor. From 62rem every tier is capped at one of three columns; `primary` keeps its hierarchy by spanning a third row instead of growing wider. Today's three secondary projects close one row exactly; adding, removing or filtering projects can leave a ragged tail, but a tile never expands to fill it.

Small text on a tile uses `--color-primary-ink`, never `--color-primary`: the plain primary only reaches 3.9:1 in the card zone.

**Page structure:** [index.astro](src/pages/index.astro) → [Base.astro](src/layouts/Base.astro) (head/meta/fonts/scripts) wraps `Intro` + `ProjectList`.

**Bilingual (ES/EN) without routing.** Both languages are rendered into the single page and CSS shows one, keyed off `html[data-lang]`:
- Every visible string in `profile.ts` is a `{ es, en }` pair, rendered through [Bilingual.astro](src/components/Bilingual.astro).
- The switch is `display: none`, deliberately — it drops the inactive language out of the accessibility tree, so a screen reader reads the page once.
- Language is resolved by a small `is:inline` script in `Base.astro`'s head — the only blocking JS, because it must beat the first paint (`motion.ts` is deferred, so a stored preference would flash the wrong language). It reads `localStorage.lang`, falls back to `navigator.language`, and sets `data-lang`, `lang` and `document.title`.
- Spanish is what gets served, so Spanish is what crawlers index. The `<meta description>` is not swapped client-side.

**Icons are inline SVG, never a runtime library.** Four distinct kinds, and the distinction is deliberate — hairline strokes mark a discipline, solid fills mark a tool, loose strokes in `--color-primary` mark an annotation, and a wordmark marks a company, so none of the four ever competes at the same visual weight. The full table is in [design.md §5](design.md):
- [Icon.astro](src/components/Icon.astro) — the three discipline glyphs, drawn by hand. Same rules as the external-link arrow in `Links.astro`: no fill, `currentColor` stroke at 1.1, round caps and joins.
- [ToolIcon.astro](src/components/ToolIcon.astro) + [src/lib/tool-icons.ts](src/lib/tool-icons.ts) — brand marks for the stack. `simple-icons` (CC0) is a **devDependency**: Astro evaluates that module at build time, so only the resulting `<path d>` ships and the package never reaches the browser. Adobe had its marks removed from `simple-icons` at its own request, so After Effects / Illustrator / Photoshop are inlined from CoreUI Brands (MIT) — also filled, but drawn on a 32-unit grid, which is why `viewBox` is stored per icon rather than assumed.
- [Doodle.astro](src/components/Doodle.astro) + [src/lib/doodles.ts](src/lib/doodles.ts) — the hand-drawn annotations (ring, arrows, highlighter). `roughjs` is a **devDependency** for exactly the reason `simple-icons` is. Every shape pins a `seed`, or rough redraws it differently on every build. These are the only marks that carry colour of their own, which is what keeps them reading as a layer on top rather than as more content. Keep the record to shapes that are actually used — an unconsumed one is dead code in a module that runs on every build. **See [design.md](design.md)** for the full system: the two render modes, the `max-width` trap, and the annotation inventory.
- [CompanyLogo.astro](src/components/CompanyLogo.astro) + [CompanyLogoSprite.astro](src/components/CompanyLogoSprite.astro) + [src/lib/company-logos.ts](src/lib/company-logos.ts) — the employer wordmarks in the track record, and the only marks whose shape is not ours. Each of the eight traced marks is emitted once as a `<symbol>` and the fourteen accessible instances reference it with `<use>`. Same build-time contract as `toolIcons`: an unknown `company` throws. Sized by *area*, not by a shared height — `width`/`height: auto` plus the mark's own `aspect-ratio` (written inline from its `viewBox`) makes `.track-company-logo`'s `max-width`/`max-height` behave like `object-fit: contain`, which is what lets an 8.9:1 wordmark and a 1.2:1 one sit in the same column. Unlike the sprite, the instances are **not** `aria-hidden`: they carry `role="img"` and the company name as `aria-label`, because here the logo replaced the text instead of decorating it. See [design.md §9](design.md).

A `tools` entry in `profile.ts` is a **key into `toolIcons`**, not a display name; an unknown key throws at build. Each mark carries a `<title>` (the hover tooltip) but no ARIA — the panel is `aria-hidden` and each axis button already lists its full stack as `sr-only` text, so labelling the marks would make a screen reader read it twice. Below 62rem the names render as visible text beside the marks, because a phone has no hover to reach the tooltip with.

**Bio glosses.** A term written as `[término](nota)` in a `profile.ts` bio becomes a hoverable footnote, parsed at build time by [src/lib/gloss.ts](src/lib/gloss.ts) into plain text nodes (never `set:html`). Keep marked terms to one word — `.gloss` is an inline-block button and will not break across lines — and one gloss per paragraph, since notes anchor to the paragraph.

**Prose streams in, word by word, and it is pure CSS.** The two blocks of copy on the page — the bio (plus the experience line beside it) and the track record's lead and notes — resolve out of blur one word at a time, the way a model writes a reply, with a caret at the head of the stream. [src/lib/stream.ts](src/lib/stream.ts) splits a string into word and whitespace chunks at build time, [Stream.astro](src/components/Stream.astro) is the bilingual wrapper (drop-in for `Bilingual` wherever the parent carries the `stream` class), and everything else is the "Streaming copy" block in `global.css`. Four things about it are load-bearing:

- **No JS is involved, and that is why it works at all.** A streamed block that has been `display: none` since load — the track record, the inactive language — restarts on the way in, which a one-shot script cannot do. It is the same reason `.track-enter` is an animation rather than `[data-reveal]`.
- **`opacity` and `filter`, never `transform`.** `transform` is ignored on a non-replaced inline box, so animating one would force `inline-block` words, and those change line breaking and defeat `text-wrap: pretty`. Verified: every streamed paragraph measures the same height with the spans as without.
- **`animation-fill-mode: backwards`, and a `.word`'s resting state is the resolved word.** `forwards` would lock in the last keyframe, and `blur(5px) → filter: none` computes as `blur(0px)` — leaving every word on the page holding a containing block and a stacking context for good. A glossed term is the one word that skips the blur entirely (`stream-in-plain`), since it carries an absolutely positioned note and its marker swipe as children.
- **The delay composes rather than being restated.** `--i` inherits from the `.enter` / `.track-enter` ancestor, so a streamed block starts when its block does. Budget: `--stream-step` (38ms) × the longest sequence. The bio runs one counter across both paragraphs — ~47 words, ~2.1s — and is the longest on the page; each track note counts from zero on its own, because the entries are already staggered 45ms apart and a running counter there would put the last note four seconds behind the first.

**The "Ahora" box answers the bio, so it waits for it.** `.now` is the one block whose entrance is not its own `--i` — it carries none — and three things read `--now-start` instead: the box's fade, its copy's stream, and the colour sweep that crosses it once (`.now-sweep`, an element rather than a pseudo because the band has to be clipped to the rounded frame, which `.now` itself cannot do — it holds a `.gloss-note` that is meant to overflow). `--now-start` is spelled out as the arithmetic it stands for, and it is **coupled to the bio's word count in Spanish** (the longer language, so the one that decides): re-measure it when the bio's copy changes. Recolouring is one line, `--now-sweep`. The whole sequence lands ~4.1s after load, which is the price of the wait. It is also the only load-in that needs JS to replay: the language swap happens at the `[data-i18n]` wrappers *inside* the box, so the words restart on their own while the frame and the sweep — never hidden — do not (job 7).

**Runtime JS is two files** (never a framework island), and the split is the point. `motion.ts` is loaded on every viewport; the shader is a desktop-only dynamic import so mobile never downloads or compiles it:

- [src/scripts/veil.ts](src/scripts/veil.ts) — the animated desktop background, and nothing else. [SolarVeil.astro](src/components/SolarVeil.astro) imports it only from 62rem upward; below that breakpoint the canvas is hidden and the static CSS gradient is the complete background. It was kept out of `motion.ts` because a GL context is not a small DOM job: it sizes itself off a `ResizeObserver`, stands down on `visibilitychange` or when crossing into the mobile layout, rebuilds itself after `webglcontextlost`, and renders a single frame instead of looping under `prefers-reduced-motion`.
- [src/scripts/motion.ts](src/scripts/motion.ts) — everything else. Its header comment enumerates the jobs; keep that list in sync when adding one:

1. Scroll-reveal elements tagged `[data-reveal]` via `IntersectionObserver`, with a scroll-based sweep as a fallback for elements that never cross a frame boundary (e.g. restored scroll position).
2. Play/pause tile videos on hover (pointer devices) or on-screen-centered (touch), via `canHover` media query branching.
2b. Rotate case imagery only while visible. Inactive frames ship as `data-src`/`data-srcset`, are promoted near the end of the hold and must decode before the dissolve starts.
3. Keep the footer's local clock ticking, aligned to the minute boundary rather than a naive `setInterval`.
4. Fetch the footer's live weather reading once, on load.
5. Drive the capability panel from whichever axis is hovered or focused — and, on pointer devices only, dim the bento tiles that do not share its axis. A click on the same chip commits that axis as the filter (job 8), which is why this one is wired last, with `initFilters`' `apply` handed to it.
6. Open a bio gloss on tap, where there is no hover to open it.
7. React to ES/EN toggle clicks (resolution happens in the head script, above), including swapping gallery `alt` text — the one string on the page CSS cannot switch, since an attribute has no second copy to hide — and replaying the `.now` box's entrance and sweep, the one part of the load-in CSS cannot replay by itself (see below).
8. Filter the bento by axis, re-packing the grid with a FLIP. It owns the grid, the chips' `aria-pressed` and the "Borrar filtros" bar — but not the axis clicks, which belong to job 5. Clearing from the bar dispatches `bentofilter` on the bento so job 5 can resync a panel no pointer event will reach.
9. Route `#caso/<slug>` between the grid and one open case.
10. Route `#recorrido` between the bio and the track record — same two-views-one-URL trick as 9, on the other column. Unlike 9 it animates the *outgoing* view: nothing morphs between two blocks of prose, so the swap carries its own direction (bio leaves leftward, record arrives from the right).
11. Count the figures up from zero — a case's `.case-metrics` and the record's `.track-stats`, the two `[data-counter]` strips.
12. Leave the NERV console easter egg.
13. Reinforce user-triggered state changes with optional `uisfx` sounds, respecting the persisted mute control.

The counter is the one job that rewrites text rather than animating a property, and three things follow from that. **The number ships written into the HTML and is read back out of the DOM** — never handed over as a second copy — so with JS off, or before the script runs, the figure is already correct and only the count is missing. **Only the numeric run is touched:** whatever surrounds it in the same string (`+`, `%`, `x`, a unit) is preserved, and the interim values are re-rendered in the shape they were authored in, so `11.432` counts in Spanish grouping and a decimal holds its precision — the last frame is byte-identical to the source string. And because it is `requestAnimationFrame` driving `textContent`, **a `setTimeout` settle timer lands the real number regardless**: a tab that is hidden when the run starts gets timers but no frames, and without it the figure would sit at zero until someone looked at it. Both strips already carry `font-variant-numeric: tabular-nums`, which is what stops a running figure from resizing its own line every frame; a new figure strip needs that too. The start is staggered off its block's own `.case-enter` / `.track-enter` `animation-delay`, read from the computed style rather than restated in JS. Re-arming is deliberately narrow — a figure that loses its box entirely (its view was switched off) counts again on the way back, matching the rest of the load-in that replays there; one merely scrolled past stays counted, like every `[data-reveal]`.

State is always expressed as a `data-*` attribute or a class that CSS reacts to — never inline styles. The FLIP helpers hold that line by using `element.animate` (the Web Animations API never touches the `style` attribute) rather than writing transforms and cleaning up after themselves. Every animated property driven by `motion.ts` is transform/opacity only, so the compositor handles frames without layout reads during scroll; the FLIPs are the one place layout *is* read, twice in the same frame, in response to a click — never during a scroll. `<noscript>` in `Base.astro` force-shows everything if JS is unavailable.

Two non-obvious details in the case router, both of which were bugs first:
- **Closing a case force-reveals any tile still pending.** A tile whose grid has been `display: none` since load — the case was deep-linked, so the index never rendered — has no box for the reveal observer to intersect and does not reliably get one on the way back. It would stay at `opacity: 0` for good. The stagger is a per-tile `transition-delay`, so resolving them all at once still arrives as a wave.
- **"Volver" pushes rather than calling `history.back()`.** Guessing whether the entry behind us is our own index stops being reliable once the prev/next links have been used, and guessing wrong there means leaving the site. Pushing always lands on the index, and the browser's own back button still returns to the case.

**The background is a static CSS gradient on mobile and a shader on desktop; the scrim over both is load-bearing.** [SolarVeil.astro](src/components/SolarVeil.astro) mounts a fixed, full-viewport canvas plus a `.veil-scrim` overlay; the shell above it is lifted out of the way with `position: relative; z-index: 1`, which also traps `.gloss .doodle`'s `z-index: -1` inside the shell instead of letting it fall behind the page.

The two halves carry opposite guarantees, and conflating them is the mistake to avoid:
- **The canvas is desktop-only enhancement.** Below 62rem it is hidden and its module is not requested. Above 62rem, no WebGL2, a lost context or a blocked script are all fine: `body` carries the static same-palette gradient underneath it.
- **The scrim is not.** Every ratio in the `@theme` block is measured *through* it, against the brightest frame the shader can produce, so it has to be there whether or not the canvas ever paints. Its two alphas and the shader's `brightness` are the only levers on that budget; moving one means re-running the measurement in design.md §7.

The shader carries no dependency. It arrived as a React component driven by `ogl`, and both were dropped: `veil.ts` talks to raw WebGL2, and the GLSL was cut down to the path its own preset actually reached (the original's ~40 uniforms were nearly all switched off). The full original is kept, unbuilt and untyped, in [docs/reference](docs/reference/).

**The left column also has two views and one URL**, and it is deliberately the same construction as the right: `#recorrido` opens the track record, both views ship in the HTML, `data-view` picks one, and a single `hashchange` is the whole route. See [design.md §9](design.md) for the full account; the three things that will bite anyone editing it:

- **The column is in three parts.** `.intro` is a sticky 100svh flex column holding `.intro-views` (the two views, `flex: 1; min-height: 0`) and `.intro-foot` (contact + local clock). The footer sits *outside* the views on purpose — it is why opening the record no longer takes contact off screen, and why it does not move during the swap: it is a sibling of the element being animated out, not a child. Dropping `min-height: 0` lets the views refuse to shrink and pushes the footer off the bottom of the screen, which is the exact failure the split exists to prevent.
- **Only the track view scrolls internally** (`.intro[data-view='track'] .intro-views`). `overflow` clips as well as scrolls, and the bio has one thing that legitimately overflows its box — a `.gloss-note`, which is allowed to be wider than the column it anchors to. The bio also already fits one viewport by design.
- **Entries enter by CSS animation, never `[data-reveal]`.** They live inside a `display: none` view until the hash opens it, so an IntersectionObserver never gets a box to intersect — the same bug the case router hit from the other direction. `enter-left` restarts on its own each time the view is shown, which is the behaviour wanted. The first route of a page load skips the transition entirely: a shared `#recorrido` link has no outgoing view to slide away, and a page opened in a background tab has its animations parked at frame zero, so waiting on one would strand the swap.

**The intro column has a hard height budget.** `.intro` is `position: sticky; height: 100svh` above 62rem, so anything added to it must fit one viewport. The budget belongs to `.intro-views` in the **bio** view — the record is a fourteen-entry timeline that scrolls inside its own box and was never asked to fit — which is why all three sticky-release thresholds below are scoped to `[data-view='bio']`, and why they must be scoped **all three or none**: at (0,2,0) one scoped rule outranks the other two regardless of source order, and the two that re-assert sticky on tall screens would stop being able to. Two mechanisms hold the line, and both are measured numbers, not guesses:
- `.axis-panel` has a fixed `min-height` and stacks all its slots absolutely, so switching disciplines cannot move the column. Copy that outgrows the box is clipped. Budget: one sentence per `line`, and enough `tools` to stay on one row (seven marks fit a 19rem column). The box gets a taller `min-height` below 62rem, where the tool names are visible and the column is no longer pinned.
- The escape hatch that releases sticky when the viewport is too short is **tiered by width**, because the column is `max(19rem, 30vw)` and a wider screen wraps the copy to fewer lines: released below 67rem of height above 62rem wide, below 57.5rem above 90rem wide, below 54.5rem above 120rem wide. **Adding a row to the intro means re-measuring all three** in both languages, at the narrowest viewport in each tier; see design.md §6 for the procedure. The two levers that bought the pinning back on a 1080p screen are `.col-prose` (38ch, raised to 62ch above 62rem — a height decision, not a typographic one) and the column's `padding-block`, at `6vh` so it only gives back space on short viewports.
- Doodles are exempt: they are absolutely positioned and cost zero flow height, which is the whole reason annotations are drawn rather than laid out.

**Fonts are self-hosted**, not pulled from `@fontsource` at runtime: the woff2 files are copied out of `node_modules/@fontsource*` into `public/fonts/` and referenced by hand in [src/styles/global.css](src/styles/global.css) `@font-face` rules. After bumping the `@fontsource-variable/inter-tight`, `@fontsource/instrument-serif` or `@fontsource/caveat` versions, re-copy the woff2 files manually (see comment at top of `global.css`). Caveat is deliberately not preloaded — it only sets margin notes.

**Design tokens** (colors, fonts, easing curves) are centralized in the `@theme` block at the top of `global.css`, consumed via Tailwind's generated `--color-*`/`--font-*` utilities. The palette is dark — five neutrals on `--color-bg: #120906`, which is deliberately the same value as the shader's darkest colour — plus `--color-primary` (`#e35342`) and two derivatives. **Which primary token to use is a contrast decision, not a taste one**, and on this background `--color-primary-ink` is the *lighter* tint, the reverse of what the name suggests to anyone who saw the previous cream palette. The ratios are in the `@theme` comment and in [design.md](design.md).

**[design.md](design.md)** holds the visual decisions: palette with measured contrast ratios, the doodle system, typography roles, the annotation inventory, the height/weight budgets, the background shader (§7 — its three colours, the scrim contract, the three levers on the contrast budget, and the procedure for re-measuring them), the bento (§8) and the track record (§9). Adding an annotation means adding a row to its inventory table; touching a scrim alpha or the shader's brightness means re-running §7's measurement.
